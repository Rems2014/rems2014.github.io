ABOUT ME / CONNECTING DISCIPLINES

From geological uncertainty
to useful data.

The subsurface is messy, sparse, and uncertain. My interest lies in combining geological understanding with modern data workflows and predictive methods to explore patterns that conventional analysis can miss.

My focus spans borehole logs, seismic datasets, stratigraphic layers, and geospatial (GIS) data. I’m interested in the full journey: ingesting and cleaning source data, modelling subsurface properties, and estimating what lies between observations.

PORTFOLIO BLUEPRINT

Batch Processing & Cloud Migration Pipelines

A geology-focused blueprint for moving borehole logs, CSV records, and GIS inputs into cloud storage, then processing scheduled batches into consistent analysis tables.

PythonSQLAirflowAzure Data Factorydbt
Explore the build +

Architecture

LAS / CSV / GIS inputs → Python parsing and validation → cloud landing zone → staged transformations → curated borehole and spatial tables. Define coordinate systems, depth units, and provenance; start with a backfill, then add checkpointed incremental loads.

Evidence to include

  • Full-load and incremental-load demonstration with safe retries
  • Source-to-target row counts, checksums, and schema reconciliation
  • Migration cutover, rollback plan, lineage, and reproducible setup

Measure after building

Record batch duration, data volume, reconciliation failures, freshness, and cloud cost using measured runs.

02 — EVENTS / STREAMING
CAPTURE → WINDOW → AGGREGATE
PORTFOLIO BLUEPRINT

Real-Time Streaming & Event-Driven Pipelines

A blueprint for processing simulated field or drilling sensor events and triggering downstream actions while accounting for duplicates, late arrivals, and failures.

KafkaSparkDocker
Explore the build +

Architecture

Simulated field-sensor events → Kafka topics → Spark streaming → time-windowed aggregates and downstream event consumer. Preserve timestamps and units; route invalid events to a dead-letter topic for inspection and replay.

Evidence to include

  • Event-time windows and watermark explanation
  • Idempotent consumer, deduplication, and checkpoint recovery test
  • Consumer lag, retry and dead-letter handling, with a failure walkthrough

Measure after building

Report observed throughput and end-to-end latency with hardware and configuration disclosed.

02 / ENGINEERING APPROACH

a design choice.

Great portfolio work makes tradeoffs visible. Explain what you built, why you chose it, and how someone else can verify it.

01

Make it reproducible

Version the code, pin dependencies, provide sample data, and document the setup.

02

Make it trustworthy

Test schemas and business rules. Handle retries, missing data, and safe re-runs.

03

Make it understandable

Include architecture, lineage, decisions, limitations, and an operational runbook.
